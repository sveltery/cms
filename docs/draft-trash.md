# Bounded draft trash service

Current pagination: [PR #28](https://github.com/sveltery/cms/pull/28) adds the [cursor/Load More contract](trash-pagination.md). The no-cursor/up-to-50 limits below describe the historical slice; the new record supersedes only those bounds, preserving prior differences and evidence.

This database-only slice was based on main `9d579f8a22e3215f3296448597361817a9babfbc` and integrates schema-admin merge `b45aac8` and EmDash 1.1.0 immutable pin `913cb1bb9b7f08c3ff0d258b4420e53835b6a58e`. It adds explicit trash reads and atomic draft restoration without changing existing service signatures or their error ordering. No remote, route, UI, publishing, permanent-delete, production factory, credentials or deployment is added. Native/web restore UI is a later slice.

## Service contract

Trusted callers compose `cmsService(database, principal)` as before. Client identity or ownership inputs are rejected. Existing active draft queries still exclude deleted rows.

| Method | Input and result | Permissions and errors |
| --- | --- | --- |
| `getTrashedDraft` | `{ type, id, locale? }`; full retained scalar draft data plus `deletedAt`. Without locale, lookup searches every locale; explicit locale must match. Active/missing rows are `NOT_FOUND`. | `content:read` and `content:read_drafts`, checked before validation/storage. |
| `listTrashedDrafts` | `{ type, locale?, limit?, cursor? }`; `{ items, nextCursor? }` of summaries with `deletedAt`, locale and revision tokens. Omission includes all locales. Default 50, cap 100, positive safe integer required; `deletedAt DESC, id DESC`. Title is at most 200 characters and body/data columns are excluded. | Same read permissions; strict validation precedes storage. The current cursor contract is documented separately; count/order override remain outside this bounded API. |
| `restoreDraft` | `{ type, id, locale?, expected: { version, updatedAt } }`; returns this write's active `DraftEntry` from SQL `RETURNING`. Locale defaults to `en`, consistent with existing mutations; callers restoring other locales must pass the locale returned by trash reads. | `content:edit_own` or `content:edit_any`; delete permission does not grant restore. General authorization precedes parsing/storage. Persisted owner must match for edit-own; null owner denies edit-own. Missing row/collection is `NOT_FOUND`; authorized active row, stale token or losing race is `CONFLICT`. |

The internal repository has separate `findTrashedById`, `findByIdIncludingTrashed`, `listTrashed` and `restore` operations. They are storage seams; request callers must use the service. Including active rows in restore preflight preserves the pinned active-row conflict while allowing ownership denial first. The restore SQL repeats owner, ID, locale, draft status, deleted state, version and timestamp predicates. A schema-version guard and mutation execute in one atomic batch. A missing-row diagnostic after CAS loss yields `NOT_FOUND`; an existing row yields `CONFLICT`, including ownership changed after authorized preflight. Unexpected storage failures retain their errors and roll back the batch/guard rows.

Restore clears `deleted_at`, `live_revision_id` and `scheduled_at`, keeps status `draft`, increments version and advances timestamp to `max(Date.now(), expected updatedAt + 1 ms)`. It preserves scalar data, author, slug, locale, creation time and translation-group columns. This slice only supports stored draft rows and scalar schemas. It neither implements nor demonstrates restoring published content, revision pointers, revision history, scheduling, translations or revalidation of retained values against a changed field schema. The default draft fixtures have null live/schedule columns; clearing them earns no lifecycle parity credit.

## Indexed-search fidelity and explicit local migration

The [paired physical-index probe](../scripts/reproduce-draft-trash-index-upstream.mjs) executes the complete pinned `SchemaRegistry.createCollection/createField` and `ContentRepository.findTrashed`, captures its compiled SQL and runs `EXPLAIN QUERY PLAN` on actual Node/local D1. Registry blob `da7bbcdda224dfca8d9146b2f36659ab90bcac2e` creates `(deleted_at, status)` at [registry.ts:1982](https://github.com/emdash-cms/emdash/blob/913cb1bb9b7f08c3ff0d258b4420e53835b6a58e/packages/core/src/schema/registry.ts#L1982). The 300-row fixture has 200 active and 100 trashed drafts, including deletion-time ties; `ANALYZE` preserves the observed plans on both runtimes.

| Physical layout | Measured all-locale query plan |
| --- | --- |
| Pinned upstream registry/repository | `SEARCH` through `idx_ec_posts_deleted_status`, then temporary B-tree for the final ID ordering term. |
| Original port, only locale-leading list index | Full table `SCAN`, then temporary B-tree for the complete ordering. |
| Repaired port, upstream-shaped `(deleted_at, status)` | Indexed `SEARCH`, retaining upstream's final-term sort. |

The parent approved this minimal indexed-search repair after the paired probe. Tie sorting is an inherited performance limitation; result caps do not guarantee bounded database work for large equal-time groups. The probe also measures a no-sort partial-index alternative, which is a separate optimization and is not installed. Query-plan/opcode observations earn zero upstream assertion credit and are not runtime step counts or deployed D1 capacity evidence.

New collections create `idx_ec_<slug>_deleted_status` in their existing atomic creation batch. Operators explicitly rerun `migrateCms(database)` on local storage to backfill existing collections. The known system/auth-state gate runs first; missing/malformed known auth states still fail without repair. Version-one upgrades include all missing indexes in the same auth/marker batch; complete version-two databases install all missing indexes in one atomic batch. Existing markers, schema metadata, field defaults/required/unique rules and retained rows are unchanged. No new migration marker is introduced for this additive index backfill. At most 100 registered collections are supported. Compatible existing indexes are idempotent; incompatible same-name objects fail `MIGRATION_REQUIRED` without replacement. Guarded concurrent installers accept only the expected index definition, and a failed batch rolls back all its additions. No service read/restore call, import, production hook or credential setup performs this DDL.
