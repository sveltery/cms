# Required scalar content validation

This bounded fidelity repair starts from CMS main `5f73e252bfc4f8392fc7c337b7b33d8798330cf8`. Authority is EmDash **1.1.0**, immutable [`913cb1bb9b7f08c3ff0d258b4420e53835b6a58e`](https://github.com/emdash-cms/emdash/commit/913cb1bb9b7f08c3ff0d258b4420e53835b6a58e). It repairs the SF-03 difference recorded by [the earlier physical scalar repair](scalar-field-fidelity.md) and [the canonical register](../parity/emdash/compatibility.md). [PR #31](https://github.com/sveltery/cms/pull/31) owns the implementation, final eligibility and landing records. Preserve [MIT attribution](../notices/emdash-MIT.txt).

The pinned [handler validator](https://github.com/emdash-cms/emdash/blob/913cb1bb9b7f08c3ff0d258b4420e53835b6a58e/packages/core/src/api/handlers/validation.ts#L199), blob `a9e40d310098e2329e166614fa10fcea1b53c84d`, uses the generated schema for types, lengths and required omission, then separately rejects explicitly supplied `''` for required fields in both full and partial modes. The [Zod generator](https://github.com/emdash-cms/emdash/blob/913cb1bb9b7f08c3ff0d258b4420e53835b6a58e/packages/core/src/schema/zod-generator.ts#L41), blob `550d4918258aa52a0d0f272b69061c76e79d86ee`, leaves string/text values untrimmed, makes optional fields nullish and applies explicit metadata defaults. The handler returns validation success or issues; it does not return parsed/default-materialized data. Both downloaded source blobs were checked against these immutable Git object IDs during this repair.

The product change is confined to `validateData` in [entries.ts](../src/lib/server/database/entries.ts): a submitted required string/text value equal to `''` fails with the existing `VALIDATION_ERROR`. This applies regardless of absent/nonempty/empty metadata default and whether minimum length is absent, zero or cleared. Existing type and length checks remain in force. Strings containing whitespace stay exactly as submitted, subject to the same length bounds; no trimming or coercion is introduced.

| Submitted content value | Required string/text | Optional string/text |
| --- | --- | --- |
| Explicit `''`, full or partial | Reject, regardless of metadata default or zero/absent minimum | Accept when existing length bounds permit |
| Explicit null, full or partial | Reject | Accept |
| Whitespace string, full or partial | Accept when existing length bounds permit, preserving exact value | Same |
| Omitted, full create | Reject without metadata default; permit with explicit metadata default, including `''` | Permit |
| Omitted, partial update | Permit; preserve stored value | Permit; preserve stored value |

Validation never adds a metadata default to input. Permitted omissions therefore retain the original physical SQL default behavior: a required field uses its existing SQL default, and a new optional field yields SQL NULL even with metadata default. Metadata edits do not replace physical defaults. The SF-02 legacy-layout difference remains recorded; this repair changes no DDL, index, migration marker, metadata or existing stored value.

Partial updates validate submitted fields only. Updating another field must preserve a legacy required `''` or SQL NULL instead of revalidating the combined row. Reads, SSR preview, trash, restore and persisted reopen continue to expose those legacy values. Explicitly resubmitting empty/null to that required field is rejected. Rejected requests must write no content or other state and retain existing versions, timestamps and `_rev` tokens. Authorization, persisted ownership, revision context/CAS and the native error envelope remain the existing contracts; default-disabled authoring remains disabled.
