# Safe session and editor metadata composition

This document retains the historical PR #7 slice, which joined the auth resolver and collection service without creating accounts or enabling production writes. Its base main is `8bd3e62fe131116670fea7b87e623ba30fd84b19`; pinned EmDash 1.1.0 is `913cb1bb9b7f08c3ff0d258b4420e53835b6a58e`. [The source ledger](session-composition-ports.json) records inspected blobs, exact retained/omitted assertions and original test-first checkpoints. The existing [MIT notice](../notices/emdash-MIT.txt) covers the descriptor/test adaptations.

Current [runtime composition](runtime-composition.md) installs the trusted factory in `hooks.server.ts`, lazily opens explicitly configured storage, runs canonical forward migrations and resolves ordinary stored sessions. Configured storage opts into the mutation gate unless `SVELTERY_MUTATIONS_ENABLED=false`; unconfigured hosting keeps the original denial behavior. Credential setup/login and enabled content editing remain separate features. The [expanded migration framework](full-schema.md) preserves v1/v2 and registers later providers; the version-two checks below describe the original checkpoint rather than the current latest version.

## Request composition

`createCmsHandle(factory)` in `src/lib/server/auth/composition.ts` calls trusted server configuration afresh for each request. The factory returns `{ database, mutationsEnabled?, keepAlive? }` with an already-migrated adapter. It must not derive the adapter or mutation flag from client headers, cookies, query or form data. Node may reuse a process-owned adapter; Cloudflare composition must supply the correct trusted raw request binding and pass this request's `waitUntil` as `keepAlive`. The handle owns `locals.cms`, clears stale context, reads only the `cms-session` cookie through Kit's cookie API, resolves the current joined session/user row and freezes a server-derived effective principal. The cookie has no identity/role payload. Current stored role, disabled status, revocation and absolute expiry are checked on every request. An in-flight authorized request is not retroactively cancelled.

The bridge selects exactly the nine permissions supported by the service using the pinned role helpers. Contributors can read drafts/create; authors additionally edit/trash their own content; editors can edit/trash any content and read administrative schema; admins can manage schema. Neither contributors nor authors receive `schema:read`.

At the original PR #7 checkpoint, `src/hooks.server.ts` deliberately installed an unconfigured factory. The current runtime supplies it through trusted host variables or platform bindings; configuration creates neither a principal nor a credential/session. HTTP mutation forms call `requestContent('mutation')`; an authenticated principal receives 503 `MUTATIONS_DISABLED` unless trusted request configuration returns `mutationsEnabled: true`. Configured runtime storage supplies that opt-in unless explicitly disabled. The gate is checked before invoking storage or mutation service methods. Anonymous callers retain 401. This gate is independent of role permissions and disabled UI controls. It protects HTTP remotes/native forms; direct trusted operator calls to `cmsService` remain explicit server APIs.

## Historical version-two migration lifecycle

An operator runs `migrateCms(database)` before serving configured requests. Version two creates empty `_cms_auth_users`, `_cms_auth_sessions` and `idx_cms_auth_sessions_user` in the same adapter atomic batch as its migration marker. Fresh databases record versions one and two. An exact version-one database has the original singleton `CHECK(version = 1)` tracking table: the upgrade rebuilds that tracking table and appends version two atomically, preserving every collection, field and draft. No account/session is inserted.

Startup rejects missing core tables, untracked/partial auth objects, a version-one marker with auth objects, malformed auth DDL/index, missing markers and unknown future versions with `MIGRATION_REQUIRED`, without repair. The registered auth DDL is checked against its known descriptor, including constraints and session-user cascade/index. This bounded validation is not a full checksum of content tables or general corruption recovery. Known object layouts and migration markers are read in one SQL statement snapshot; a deterministic independent-connection test commits an upgrade after the initial preflight read. The upgrade guard runs inside the transaction. Only the specific stale-guard/fresh-table race is recovered, and only after verifying the fully committed version-two schema. Other failures propagate; DDL and marker failures roll back the whole batch. The Node tests cover independent concurrent clean/upgrade callers and reopening preserved content.

## Read-only editor manifest

Pinned upstream exposes live editing descriptors through [the manifest route](https://github.com/emdash-cms/emdash/blob/913cb1bb9b7f08c3ff0d258b4420e53835b6a58e/packages/core/src/astro/routes/api/manifest.ts), protected by auth middleware and consumed by the admin router. [Its descriptor builder](https://github.com/emdash-cms/emdash/blob/913cb1bb9b7f08c3ff0d258b4420e53835b6a58e/packages/core/src/api/handlers/manifest.ts) is distinct from administrative schema reads.

`getEditorManifest` is a SvelteKit `query` remote returning `{ collections: { [slug]: { label, labelSingular, supports, fields: { [slug]: { id, kind, label, required, validation? } } } } }`. Existing registry bounds cap it at 100 collections and 32 fields each; it reads fresh every time, using one collection query plus field queries in batches of 50 visible collection IDs (at most three reads). Empty/1/50/51/100 collection boundaries use 1/2/2/3/3 reads. The pinned source also batches at 50; its five-collection test asserts output, not a universal two-query guarantee. See [batching source/evidence and retained ordering/error/cap adaptations](editor-manifest-batching.md). No JOIN, snapshot isolation or full manifest/hash contract is claimed. String fields keep `kind: string`, text keeps upstream `kind: richText`; this preview uses a disabled plain textarea and implements no rich-text editor. Supported validation includes only min/max length. Missing validation is omitted.

This bounded draft-editor path requires both `content:read` and `content:read_drafts` before storage access. That is a deliberate least-disclosure restriction relative to upstream's broader authenticated manifest: subscribers have no draft editor and receive 403; authors/contributors can load metadata without administrative schema privileges. The administrative `listCollections`/`getCollection` permissions remain unchanged. No defaults, unique/index/column metadata, descriptions, source, schema revisions/timestamps, account/session fields or entry bodies are projected. The root and dynamic content previews use this query and keep all editing controls disabled. Under the [future scalar-field repair](scalar-field-fidelity.md), required SQL defaults apply to omitted columns, while optional default metadata does not apply during creation and optional omissions yield NULL. Scalar unique remains metadata only. Existing physical defaults/indexes remain divergent pending a separately reviewed upgrade. The projected preview receives no schema-default values. Persisted explicit nulls remain blank.

## Historical evidence and remaining limits

Checkpoint `40bc29c` ran 13 new unit/service cases with 13 failures against inert seams. `f001c4a` added HTTP cases; these initially stopped at missing auth tables. After prerequisite commit `be6b060`, the three HTTP cases reached failing assertions against the base build, demonstrating successful unauthorized-by-gate creation and the missing metadata remote. The ledger does not count prerequisite/import failures as behavior red evidence.

The original full frozen bootstrap on Node 24.19.0 / pnpm 12.6.0 passed zero Svelte/type errors or warnings, 138 unit/database/development/core cases and 36 production HTTP cases, with no skips. The source ports retained two complete assertion sets (empty collection and cross-consumer freshness) and the scalar validation subset of a third upstream case; the integer assertion was unported. Migration and HTTP cases are supplemental requirements. Temporary synthetic session rows and hook fixtures remain test-only. The original artifact assertion also excluded Node SQLite openers; current [runtime artifact checks](runtime-composition.md) expect server-side configured opening while retaining fixture exclusion everywhere and opener/private-variable exclusion in clients.

The original local workerd fixture with no `nodejs_compat` verifies the portable resolver, nine-permission bridge, request handle, role change and request lifetime callback against a synthetic read-shaped adapter. It proves no D1 persistence, transaction, request bookmark or deployed hosting guarantee. Current runtime tests separately exercise actual local D1 storage and the [configured Node package](node-hosting.md) through persisted-session HTTP create/read and process restart. Native Cloudflare hosting remains unfinished. Hosted browser CI requires sandboxed Chromium; final hosted and review results belong to each feature's handoff.

Login/provisioning, cookie creation/rotation, authenticated logout wiring, API tokens, native Cloudflare hosting and actual deployment remain unfinished. The [bounded raw-binding D1 adapter](d1-database.md) verifies local migrations and persisted sessions; the runtime now accepts trusted raw D1 platform configuration. Stored-session resolution cannot issue credentials or sign anyone in, so authentication completion remains a separate gate.

Local integration defects (unregistered auth descriptors and ungated registered writes) are established by the red checkpoints above. The pinned manual `constructor` collection omission is retained and tracked in [CMS issue #8](https://github.com/sveltery/cms/issues/8). Upstream `api/handlers/manifest.ts:147` treats an inherited `Object.prototype.constructor` as a configured collection. Its actual transpiled builder returns an empty map for a synthetic manual constructor row; this is isolated source execution with substituted dependencies, not a full upstream suite pass. Local SQLite accepts the same slug; the editor projection now explicitly omits inherited Object.prototype names to retain the observable result. A separate fix can expose the collection after documented review. The Svelte lookup uses own-key checks so an omitted/missing descriptor safely renders unavailable content rather than treating a prototype function as a collection. Administrative schema storage/reads remain intact.

Independent review reproduced the migration preflight snapshot race at implementation `7fe8ce4`. Regression `bf89f6d` fails after a real independent connection commits version two between captured table inventory and marker reads; startup validation now reads both from one statement snapshot. This is a local composition defect correction, not a shared upstream bug fix. Regression `247d430` separately fails when the projection exposes constructor, establishing the pinned limitation before restoring it. Both changes require final exact-head review and hosted CI.

The landed [pattern-validation extension](pattern-validation.md) extends the scalar manifest's validation whitelist alongside persisted schema/content validation. Its [core](pattern-validation-core.md) and [native](pattern-validation-native.md) records separate projection and disabled-preview evidence from this composition slice's historical length-only checks. The descriptor does not grant edit capability: content controls stay disabled and manifest draft-read/content-read permissions remain intact. The pattern feature added no runtime composition; current configured storage supplies the separate mutation opt-in.

The validation whitelist now includes `pattern` only when its persisted value is a string, preserving the source unchanged including `''` and malformed legacy sources. Manifest projection does not compile or repair expressions and still omits unrelated validation properties and default/storage metadata. Disabled preview controls receive the metadata without HTML `pattern` constraints, so ECMAScript server matching semantics are not replaced by browser full-string/Unicode pattern behavior.
