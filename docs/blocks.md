# Reusable content blocks

The feature ports EmDash 1.1.0 at immutable `913cb1bb9b7f08c3ff0d258b4420e53835b6a58e`: reusable block type definitions, retained schema versions, contract fingerprints, blocks field constraints, stable content identities and explicit version migration/replacement. Native Svelte administration and insertion/edit/reorder/duplicate/remove controls are part of this delivery.

Complete upstream test files are committed before implementation in `parity/emdash/blocks/source-tests/`; [the source ledger](blocks-source-files.json) identifies each immutable blob and copied SHA-256. Inventory is not test execution. Genuine native failing assertions, import/setup failures and source callback execution will be recorded separately.

Canonical provider 10 follows the real options 6, taxonomy 7, metadata 8 and media 9 providers. The currently public media development dependency is not approval of those PRs; final own-only integration onto their approved main is required before merging blocks. Historical providers are immutable.

The source deliberately exposes no block type DELETE route, preserving retained content definitions. Removing a block from a content value is supported. The React block component kit, portable text widgets, plugin runtime, Astro public rendering, full import/transfer and media usage indexing are separate feature families; this delivery must not claim those from JSON storage or source inventory alone.
