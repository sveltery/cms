The planned host service exposes reads across content statuses, draft-aware saves, publish, unpublish, draft discard, revision history and restore. Native remote functions replace Astro handlers. Generic field validation and schema ownership remain with the schema provider; the lifecycle migration provider owns version 5, while the schema developer registers it centrally. Autosave replaces pending revisions without changing an existing live revision.

Further source families require their own exact source ports and failing baselines: scheduling and due sweeps, edit locks and ownership, localization and inherited field propagation, and permanent deletion. Search, cache, settings and media integrations require real host providers; unavailable dependencies must be exposed as unsupported behavior until those providers land.
