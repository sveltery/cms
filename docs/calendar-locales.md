# Calendar display locale preparation

This local preparation packet retains the full EmDash 1.1.0 locale data at immutable source commit `913cb1bb9b7f08c3ff0d258b4420e53835b6a58e`. The [source ledger](calendar-locales-source.json) records all 38 whole authority files, including 31 PO catalogs totaling 16,642,703 bytes, the four runtime modules, original locale test family, original Lingui configuration, and MIT license. None of those authorities are edited.

The Native reusable modules under [src/lib/ui/locales](../src/lib/ui/locales/index.ts) preserve the source definitions and matching behavior: 29 enabled locales, English default and unknown-catalog fallback, original endonyms and text directions, BCP 47 canonical/script/base matching, and display preference-cookie then header precedence. `resolveLocale(Request)` reads only display preferences. It does not fetch, authenticate, create a session, or authorize a request.

`config.ts` and `locales.ts` have the original bodies and an attribution header. `loadMessages.ts` has that header and only catalog path rebasing to `./catalogs/**/messages.mjs`. Native `index.ts` exports these pure locale APIs and generated message IDs without importing the absent Source React providers or email modules. It does not initialize Lingui, change an SSR singleton, modify document direction, select a user preference, or install a new global producer. Those application integration steps belong to the Calendar UI owner.

The [compiler script](../scripts/compile-calendar-locales.mjs) resolves the existing frozen `@lingui/message-utils@5.9.5` through `createRequire` anchored at `@lingui/core`. It uses the supported `compileMessage` and `generateMessageId` subpaths, with no dependency or lockfile change. It parses whole PO entries, preserves ICU expressions through the official compiler, uses original English fallback for empty/fuzzy translations, and hashes original `msgid` plus `msgctxt`. The actual pinned corpus has 3,184 non-header messages per catalog and no context, fuzzy, obsolete, or gettext plural records. ICU plural/select messages remain present. Unsupported PO syntax or duplicate compiled IDs stops generation rather than dropping entries.

`MESSAGE_IDS: Record<string, string>` contains each context-free original English msgid and its original Lingui ID. `MESSAGE_IDS_BY_CONTEXT: Record<string, Record<string, string>>` maps exact msgctxt to English msgid to ID; it is empty for this pin. Generated catalog modules contain the whole compiled message map, rather than a Calendar-only subset.

The disabled Korean and pseudo catalogs are retained. The original Astro integration injects a development-only pseudo locale and the Source Lingui CLI garbles its text during compilation. Native has no such injection. Its generated disabled pseudo catalog currently uses source English fallback without garbling. Developer pseudo selection/garbling is **incomplete**, and explicit `loadMessages('pseudo')` differs from a Source pseudo build. This is recorded as pending scope/acceptance in the [compatibility register](../parity/emdash/compatibility.md); no pseudo parity is claimed.

The initial snapshot and its unpublished preparation packet remain historical evidence.
