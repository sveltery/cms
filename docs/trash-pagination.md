`listTrashedDrafts({ type, locale?, limit?, cursor? })` returns `Page<TrashedDraftSummary>`; native `listTrashedContent({ collection, locale?, limit?, cursor? })` returns `{ items, nextCursor? }`, with `_rev` replacing storage version. Omitted locale includes every locale, default limit is 50, cap is 100. Existing positive safe-integer validation remains; upstream also tolerates invalid/zero limits at its repository boundary, which this port already rejects. Only retained draft rows qualify, with body-free titles capped at 200 characters. Active-list cursors remain context-qualified and separate.

The [trash helper](../src/lib/server/database/trash-cursor.ts) preserves upstream wire bytes and decoding: only string orderValue/id are required; empty fields, arbitrary timestamp/ID values and extra context keys are accepted. No timestamp, ID-format or collection/locale validation is added. Direct `decodeCursor('')` throws; the repository/native query treats an empty cursor as the first page, following upstream's truthy cursor guard. The decoder cap is 4096. Native structural input caps cursor at 2048 before callback authorization; valid-shape semantic decoding follows existing service permission checks, before storage. InvalidCursorError preserves its name and truncated upstream message; local readonly code metadata permits the domain error identity. Native `contentResponse` explicitly maps that class to `{ type: 'error', status: 400, error: { message: 'invalid-cursor', code: 'INVALID_CURSOR' } }`. Kit query HTTP status is normally 200 with this envelope; SSR domain-error HTTP handling is a separate native framework boundary. Raw cursor content is not echoed by the native error response.

## Native Load More and refresh

[TrashPages](../src/lib/ui/TrashPages.svelte) retains native query instances for each displayed page, awaits initial SSR data, then reads each instance's live `.current`/`.error` values. [The route](../src/routes/trash/[collection]/+page.svelte) keys page state by collection. [CollectionTrash](../src/lib/ui/CollectionTrash.svelte) appends the fetched summaries with Load More rather than replacing the table with First/Next controls. The button has a pending/repeat-event guard; a failed continuation preserves loaded rows and displays a retry error. Retry explicitly refreshes a cached failed query, because Kit retains its rejected promise while a proxy remains alive. The browser retry probe retains cache proxy anchors so garbage collection cannot hide this case. Initial SSR renders up to 50; pagination requires JavaScript and the noscript message states that requirement. Reload restarts at the first page; collection navigation discards prior cursors. There is no URL cursor or no-JavaScript continuation link. This is a disclosed native interaction bound, not SSR completeness.

Each row carries its exact displayed query arguments, including limit, optional locale and cursor. [RestoreDraft](../src/lib/ui/RestoreDraft.svelte) calls `submit().updates(listTrashedContent(queryArgs))`; the existing remote refresh loop preserves those original requested keys. Default/first-page refresh alone cannot update later pages. Native per-row identity/token/locale/pending/issues and mutation/ownership/CAS guards remain unchanged. Independent Kit refreshes can overlap page boundaries after a removal; the accumulated table deduplicates by ID+locale. Retained pages are not an atomic snapshot, and requested refreshes retain the existing five-instance bound. The terminal message means the final successfully fetched page supplies no continuation; it is not a count, stable total or guarantee under concurrent insertions/deletions. This completion wires a control left unwired in the pinned router; it does not claim the upstream routed trash already supports pagination or fix that upstream router.
