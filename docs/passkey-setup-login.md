## Product and source boundaries

`/setup` and `/login` use native Kit remote forms with the real browser credential API. JSON routes are `/api/setup/{admin,admin/verify,status}` and `/api/auth/{passkey/options,passkey/verify,me,logout}`. No authenticator, credential verification, principal or session is faked in the runtime product fixture. The native browser fixture uses the pinned CDP virtual authenticator with resident-key and user-verification support.

Setup stores a one-hour HttpOnly Strict nonce cookie, using Secure for a configured HTTPS origin. Registration challenges live for five minutes. A matching nonce and verified credential permit the guarded first-user insert. The existing minimal role/disabled user and hash/expiry session tables stay intact; additive profile, credential, challenge, setup-option and rate-limit tables use `_cms_auth_*`. The first-user/profile batch is atomic, while credential registration remains a separate source step. Setup creates the administrator and credential, marks setup complete and deletes its nonce; it does **not** issue a login session. A completed flag with zero users retains the pinned administrator-recovery behavior.

Login options disclose no email-based credential/account lookup and allow discoverable credentials. Real signed assertions enforce the configured RP hash and accepted origin, challenge expiry/consumption, signature and source counter rules. The production challenge store preserves the pinned non-atomic get/delete boundary; passing typed atomic-context algorithm tests does not claim an atomic production store or typed-context endpoint. Session issuance stores only a hash of a canonical 32-byte opaque token, retains the existing absolute expiry policy and atomically revokes a supplied predecessor. Current stored role/disabled state is resolved on every request. The source algorithm itself returns a disabled user; the existing local request resolver denies the resulting session. These layering distinctions must remain explicit.

HTTP JSON schemas strip unknown DTO properties like the source Zod objects; native form envelopes retain Valibot strict keys and field issues. Every setup/login/logout mutation requires the exact trusted public Origin. The platform supplies the client address for challenge throttling; request/forwarded headers do not supply the public origin or role. The source IP-header/framework plumbing and response envelopes are adaptations. Session cookies retain the existing local HttpOnly/Lax/Secure contract and app base path. The options endpoint applies the source's ten-per-minute trusted-address counter, including a one-percent best-effort cleanup of entries older than an hour. Missing trusted address skips rate limiting. This uses Kit's platform address rather than source Astro/proxy-header extraction. Unconfigured requests fail closed. Runtime's content/schema mutation flag does not substitute for identity Origin/session guards.

`/api/auth/me` and the native `getCurrentUser` query select only the resolved principal's stored profile and current role; caller IDs/role headers grant no authority. Anonymous HTTP returns 401 and the native query returns null. The signed-in login page provides Sign out. JSON POST logout keeps the pinned optional safe-local redirect behavior; native logout revokes/deletes the session then redirects with 303 to the app's login page so a fresh request resolves identity. This native redirect is a framework adaptation, separately tested before repair. Welcome dismissal is not implemented, so the projected first-login flag remains true until a future owner adds that state.

This is the passkey-first identity milestone. Site-title/seed application, the complete source setup wizard, welcome state, additional passkey management, users/invites/recovery flows, allowed-domain signup, email/OAuth/PAT/device authentication and provider settings remain incomplete and require fresh feature owners. No full Astro route, complete source e2e wizard, Cloudflare deployment or full authentication-product parity is claimed. The [full product plan](product-plan.md) retains those required follow-ups.
