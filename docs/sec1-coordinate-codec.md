# SEC1 public-coordinate byte serialization

Pinned EmDash 1.1.0 commit [913cb1bb9b7f08c3ff0d258b4420e53835b6a58e](https://github.com/emdash-cms/emdash/commit/913cb1bb9b7f08c3ff0d258b4420e53835b6a58e) stores ES256 public coordinates with [register.ts:223](https://github.com/emdash-cms/emdash/blob/913cb1bb9b7f08c3ff0d258b4420e53835b6a58e/packages/auth/src/passkey/register.ts#L223). Its pinned `@oslojs/crypto@1.0.1` encoder right-aligns minimal-width `x` bytes but places minimal-width `y` bytes at offset 33. Short nonzero `y` values receive trailing zeros instead of leading zeros.

The [offline reproducer](../scripts/reproduce-sec1-coordinate-padding-upstream.mjs) checks the full immutable registration source, both pinned dependency integrities and the installed complete encoder/binary implementation hashes before encoding public synthetic coordinates. For `x=0`, `y=0xa5`, expected SEC1 bytes are `04` + 32 zero bytes + 31 zero bytes + `a5`. Actual pinned bytes are `04` + 32 zero bytes + `a5` + 31 zero bytes. Both outputs are 65 bytes; the stored mathematical value differs.

## Proposed intentional difference SEC1-01

The proposed original Native [coordinate serializer](../src/lib/server/auth/sec1-public-coordinates.ts) writes both unsigned coordinates into their fixed 32-byte fields. Only the ES256 serialization import and expression in the actual Native registration function change. Algorithm, EC2 and P-256 checks, RSA serialization and the surrounding registration behavior remain intact. The existing COSE decoder requires exactly 32 input bytes for each unsigned coordinate. The helper's representability guard excludes values outside that already decoded production domain; it adds no registration or authentication policy.

This repairs a verified shared Source dependency byte defect and intentionally changes the pinned behavior. It is not a fidelity repair. Root accepted the concrete SEC1-01 development difference after the reached byte baseline; [issue #93](https://github.com/sveltery/cms/issues/93) tracks the verified Source dependency bug. The exact helper and callsite are now applied. Final PR approval and landing remain separate and pending. [The compatibility register](../parity/emdash/compatibility.md) records SEC1-01 beside the unchanged prior auth decisions. Existing incorrectly stored values are not rewritten.
