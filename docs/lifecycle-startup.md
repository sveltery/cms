# Canonical lifecycle startup

This slice registers content lifecycle provider **5** with `migrateCms`. Fresh startup installs `_cms_revisions`, `_cms_revision_prune_queue` and their two indexes. New collections retain the existing system columns, allow general text status values with the `draft` default, and include nullable `primary_byline_id`. It prepares storage for the separately owned lifecycle services; it does not introduce publishing remotes, admin controls or a scheduler.

## Known-layout upgrade

Before writing, the provider independently enumerates registered collections and checks their tables. Required local system definitions, the slug/locale constraint, metadata field names and physical column types must match supported layouts. Missing tables, views, unregistered content tables/columns, incompatible system definitions, temporary objects and partially installed lifecycle tables reject with `MIGRATION_REQUIRED`. Latest provider validation also checks all four static lifecycle objects and validates known metadata/auth descriptors before reading dynamic content metadata.

Fresh preparation also scans content objects before metadata exists. An orphan `ec_*` table or view rejects without installing foundation tables or migration markers. An empty metadata/content snapshot remains guarded inside the same transaction after foundation DDL; an orphan committed after preflight causes complete installation rollback and `MIGRATION_REQUIRED`, preserving the other writer's object and rows. Repeated startup still rejects that untouched unsupported layout.

The upgrade removes only the historical `CHECK(status = 'draft')` and adds nullable `primary_byline_id`. It copies every existing column explicitly into a replacement table and restores the original SQL for indexes and triggers in the same adapter-proven atomic batch. Existing IDs, content, locale, timestamps, numeric version, revision pointers, field defaults, NULL values, unique enforcement, metadata and authentication rows remain intact. A transaction-local snapshot guard covers registered schema versions/fields, content DDL/indexes/triggers and operator tables referencing content, preventing a preflight race from overwriting a new schema write. Failed batches roll back provider objects, rebuilt tables, rows, guards and version markers. A stale startup caller accepts a winner only after validating a complete latest layout.

Operator-created inbound content FKs or unrecognized field constraints reject before rebuilding, because SQLite dropping a referenced parent can activate cascading actions. The provider preserves supported registry metadata/auth FKs; it does not repair an arbitrary operator database. All validation uses disposable local fixtures and opens no operator database.

Reserved content namespace detection follows SQLite's case-insensitive ASCII identifiers, including `EC_*` tables/views and their preflight races. External FK classification reads the identifier immediately after an actual `REFERENCES` token, accepting SQLite quoted targets and skipping comments and ordinary string literals. An unrelated operator FK to `operator_users` or `_cms_auth_users` remains supported even with an `ec_note` column or content-like text in comments/defaults. Its original DDL and rows are retained. Candidate FK-table DDL stays in the transaction snapshot so an actual content-reference writer cannot bypass the guard; a concurrent unrelated candidate-schema edit can conservatively abort that attempt, then pass unchanged on retry.

SF-02 physical field defaults/indexes and inherited scalar uniqueness [issue #20](https://github.com/sveltery/cms/issues/20) remain separate. This upgrade performs no general default/index/uniqueness reconciliation. Historical stricter local system NOT NULL/version/slug constraints and missing revision-pointer FKs remain as recorded local storage differences. The source queue migration's retry/backfill assertion, other system tables, PostgreSQL/libSQL and deployed D1 are unported here. Specific acceptance of the local migration/atomicity substitutions is not recorded.
