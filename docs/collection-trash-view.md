The separate `/trash/[collection]` route calls existing `getEditorManifest` and `listTrashedContent({ collection, limit: 50 })`. Omitted locale retains every-locale semantics. No `getCollection` call adds administrative `schema:read` to content readers. The route owns reactive parameters, async queries, handled failure and Kit `resolve`; [CollectionTrash](../src/lib/ui/CollectionTrash.svelte) receives ordinary content/href props. [CollectionDrafts](../src/lib/ui/CollectionDrafts.svelte), remotes, permissions and databases are unchanged. A collection-page link and return link use native Kit navigation and nonempty-base support.

The page says “Showing up to 50 most recently deleted drafts across all locales.” It makes no total, completeness or exhaustion claim. There is no cursor in the existing trash transport, so there is no pager or load-more control. It shows text-only Title, Locale and Deleted columns, body-free summaries, `title || slug || id`, and newest deletion order inherited from the unchanged query (`deleted_at DESC, id DESC`). Dates display `YYYY-MM-DD` in UTC with the full stored timestamp in native `<time datetime>`. Authorized empty results show “Trash is empty”; rejected, missing-schema and unconfigured queries show “Trash is unavailable.” No internal errors are rendered.

## Verification boundary

[Dedicated persisted fixture](../tests/helpers/collection-trash.ts) creates temporary Node SQLite collections, synthetic author/subscriber sessions, 55 mixed-locale deleted drafts, tied dates, title fallbacks, an active ID `trash`, a titleless collection and empty/other collections. Only the isolated built-server test hook installs trusted composition. The author lacks `schema:read` and can view other authors' trash through existing read permission. No production account, storage, credentials or mutation enablement is introduced.

[Production tests](../tests/production/collection-trash.test.ts) use actual built routes and registered query exports, assert ordered capped summaries/no data or body, escaped SSR, empty versus denied/missing/unconfigured states, active `trash` detail and persisted restart. [Browser tests](../tests/browser/collection-trash.spec.ts) verify exact ordered titles/locales/dates after hydration, reload and same-route collection navigation, return links, escaping/no mutation requests, denial and `/cms` on default/Node builds. Existing CI discovers both without configuration changes. Full bootstrap, secured hosted default/Node Chromium and independent/configured automatic review must pass on the final head before merge. Native restore tests now extend this fixture with explicit test-only write enablement and retain these view assertions. The local pinned Chromium download is blocked by CDN HTTP 403 `Domain forbidden`; this is not browser pass evidence. Exact run/head/review evidence belongs in the PR handoff.

The [native restore interaction](native-trash-restore.md) now covers explicit locale and mandatory `_rev`, refreshed results and the existing trusted mutation gate. Production composition remains unconfigured; native forms do not enable production writes.
