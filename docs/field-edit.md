## Supplied metadata only

`cmsService.updateField({ collection, field, ...metadata })` delegates to `SchemaRegistry.updateField(collection, field, metadata)`. Existing `string` and `text` fields accept optional `label`, `sortOrder`, string `defaultValue`, and nullable `validation` containing optional `minLength`/`maxLength`. Omitted properties preserve stored values; `{}` is a valid no-op metadata request after target lookup. Validation objects **replace** the previous object: `{ maxLength: 1 }` removes any prior `minLength`. `validation: null` stores SQL NULL; `validation: {}` stores the distinct JSON object `'{}'`. Upstream projects cleared SQL NULL validation as `undefined`; the local public field projects it as `null`, retaining the existing SA-02 nullable-projection difference.

The pinned [registry assignments at lines 1542–1559](https://github.com/emdash-cms/emdash/blob/913cb1bb9b7f08c3ff0d258b4420e53835b6a58e/packages/core/src/schema/registry.ts#L1542) update supplied columns only. The [request schema at line 232](https://github.com/emdash-cms/emdash/blob/913cb1bb9b7f08c3ff0d258b4420e53835b6a58e/packages/core/src/api/schemas/schema.ts#L232) permits omitted labels. Supplied labels are nonempty strings, **untrimmed and unbounded**; whitespace-only labels remain exact. Sort order and length bounds are nonnegative safe integers, matching the exercised Zod 4 integer contract. The [min/max refinement](https://github.com/emdash-cms/emdash/blob/913cb1bb9b7f08c3ff0d258b4420e53835b6a58e/packages/core/src/api/schemas/schema.ts#L133) compares the two supplied bounds only when both exist. It does not combine a replacement with old bounds, infer an omitted maximum, check existing content or cross-validate the metadata default. Creation keeps its separate bounded validation.

The default is **metadata only**. Changing it never changes a SQL default, creates/drops an index, rebuilds a table or rewrites a stored row. An empty string is a valid metadata default and differs from omission. `defaultValue: null` is outside this string-only edit slice; there is no invented clear sentinel or empty-string-as-clear behavior. The domain adds no creation maximum-length/NUL restriction or default-versus-validation check to this edit. Existing field slug/type/required/unique/widget/search/index/translation properties are unsupported and reject at the strict local boundary.

There is no field CAS or request version/timestamp precondition. Independent partial writes update separate columns and preserve each other; same-property edits are last-writer-wins. Field edits neither touch collection `updatedAt` nor increment collection schema version. Existing content values/revision tokens, collection metadata tokens and additive-field tokens remain intact. Metadata tokens protect their own metadata operation and do not certify the freshness of the fields display.

Tighter validation applies when future content writes validate against the refreshed persisted definition. Old content remains readable even if it fails the new bounds. Omitted content/raw inserts continue using the **existing physical SQL default**, rather than the new metadata value: optional columns yield NULL; required columns use the original explicit SQL default or implicit empty string. The source reproducer verifies all 12 combinations of string/text, optional/required, and initial omitted/nonempty/empty default after a metadata edit. Local public projection differences and required-empty-string SF-03 remain separate; inherited unenforced unique metadata remains deferred in issue #20.

## Trusted service and native form

The service authorizes trusted `schema:manage` before parsing or accessing storage. The existing server-derived HTTP mutation gate remains required and production writes remain default-disabled. The operation retains the atomic adapter/target-identity/own-receipt contract of the landed label operation; it adds no collection/content precondition. Missing/disappeared/replaced targets use the existing local `NOT_FOUND` behavior. Field edits refresh the schema list/detail, content collection list/detail and editor manifest through the existing query helper.

`updateSchemaFieldOptions` is a registered native SvelteKit form. Each field owns ``.for(`${collection}/${field.slug}`)`` state in `SchemaFieldOptions.svelte`; the form and each descriptor are spread directly onto native elements, including explicit hidden collection/field values. Its optional Kit `id` must match that pair and is removed before calling the service. The default textarea also supplies a Svelte `value` from its own native form field value, falling back to the stored default and then `''`; its explicit label `for`/textarea `id` remain associated. This renders the stored or submitted value as native textarea content during SSR, including after an invalid no-JavaScript submission, while preserving the direct descriptor spread. The unchanged label-only remote/service remain separate supported APIs.

Native controls submit `keep`/`set` modes for label, order and default, and `keep`/`set`/`clear` for validation. `keep` omits the domain property even if the browser submits a displayed value. `set` supplies the label/order/default exactly, with canonical decimal-to-safe-integer conversion for order. Default `set` with `''` stores that string; default has no clear mode. Validation `set` supplies only populated canonical decimal bounds; both empty supplies `{}`. Validation `clear` supplies `null`; `keep` omits it. These states work without JavaScript, without adding an ambiguous sentinel. Each instance owns pending/issues/results and keeps capability-disabled controls disabled. Native/enhanced consecutive-edit, issue/isolation, consumer refresh, origin and authorization checks are supplemental framework evidence, not upstream REST/React parity.
