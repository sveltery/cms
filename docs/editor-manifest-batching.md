# Bounded editor-manifest field reads

Proposed [PR #17](https://github.com/sveltery/cms/pull/17) replaces one field query per visible collection in `server/content/manifest.ts` with sequential batches of 50 collection IDs. The existing registry still selects at most 100 collections. Normal manifests use one collection query plus `ceil(visibleCollectionCount / 50)` field queries: 0/1/50/51/100 visible collections require 1/2/2/3/3 reads. Empty registries do not query fields. Inherited Object.prototype collection names, including `constructor`, remain omitted before field reads, preserving the previous local behavior.

Source authority is EmDash 1.1.0 immutable `913cb1bb9b7f08c3ff0d258b4420e53835b6a58e`: [registry.ts:418](https://github.com/emdash-cms/emdash/blob/913cb1bb9b7f08c3ff0d258b4420e53835b6a58e/packages/core/src/schema/registry.ts#L418), [chunks.ts](https://github.com/emdash-cms/emdash/blob/913cb1bb9b7f08c3ff0d258b4420e53835b6a58e/packages/core/src/utils/chunks.ts), [manifest builder](https://github.com/emdash-cms/emdash/blob/913cb1bb9b7f08c3ff0d258b4420e53835b6a58e/packages/core/src/api/handlers/manifest.ts), and [manifest-build.test.ts:537](https://github.com/emdash-cms/emdash/blob/913cb1bb9b7f08c3ff0d258b4420e53835b6a58e/packages/core/tests/unit/runtime/manifest-build.test.ts#L537). The actual registry chunks at `SQL_BATCH_SIZE = 50`; its documentation explains the larger-site formula. The test title says “two queries flat” but its assertions check five collection names and the five title-field kinds. It contains no query-count assertion. Neither the source nor this port implements a JOIN or universally guarantees two queries.

## Retained adaptations and observable limits

| Contract | Pinned upstream | Local behavior and rationale |
| --- | --- | --- |
| Collection and field order | Collections use schema sort order then slug; fields use sort_order then created_at. | Preserve existing slug collection order and sort_order/id field order. Tied fields with opposing created_at/ID order are compared with the pre-change registry projection. This inherited order difference is not repaired by the batching slice. |
| Bounds | Registry reads every collection and every returned collection's fields. | Retain100-collection bound and batch50 collection IDs. Root-qualified SB-02 removes the historical32-field partition/rank bound and reads every field of each selected collection. Each query binds at most50 IDs; no fixed1,600-row field bound remains. Corrupt metadata anywhere within an included collection is now rejected. Existing local ordering persists; see [current seed evidence](source-seed-backend.md) and [compatibility SB-02](../parity/emdash/compatibility.md). |
| Descriptor and disclosure | Full upstream descriptors and manifest include richer metadata and field types. | Preserve only collection labels/supports and scalar field id/kind/label/required/minLength/maxLength. Defaults, storage/admin data and unknown validation properties stay omitted. Existing string/text mapping is unchanged. |
| Omitted inherited names | Builder loads and maps stored fields before its inherited-property collision check; a manual constructor row is omitted. | Preserve omission and the earlier local policy of never reading/parsing fields of omitted collections. A constructor-only registry therefore uses one read. Tests retain omission even when its fields have malformed JSON or the field table is absent. [Issue #8](https://github.com/sveltery/cms/issues/8) remains deferred. |
| Authorization | Upstream manifest uses its authenticated route policy. | Preserve valid identity plus content:read and content:read_drafts before SQL. This grants no administrative schema capability. Supplemental Node/D1/actual-worker tests cover denial before migrated storage exists. |
| Failure | Upstream builder catches database errors and returns available config descriptors. | Preserve propagated storage and malformed-JSON failures; there is no config source. Defaults are still parsed before validation although omitted from output, so corrupt default JSON still rejects. Fields beyond the local cap remain unparsed. Batch reads precede descriptor projection; arbitrary failures injected between statements do not have the previous N+1 timing. No error-envelope, fallback or snapshot-isolation parity is claimed. |
| Freshness | Manifest reads live database rows per build. | Every invocation rereads collections and fields; metadata updates and removals appear on the next read. Sequential statements are not a transaction or a common snapshot. No caching is introduced. |
| Framework | Upstream Astro/React runtime consumes full manifest. | Existing SvelteKit getEditorManifest query and disabled previews remain the consumers. No transport, native reset, direct form spread, production factory, write gate, service, registry or collection route changes belong to this slice. |

These inherited differences remain subject to [C-14/C-15 and the compatibility register](../parity/emdash/compatibility.md); this focused branch does not record blanket acceptance. Shared documentation ownership transferred to this slice after metadata/cursor main `ae61dd04bf150058907b147a9c978b18ffacc0d5`; C-15 and the existing composition ledger now link this evidence and correct the historical “two-query JOIN/up to 101 reads” claim. Existing metadata/cursor records are retained. Proposed status is separate from landing or a specific deviation acceptance decision.
