The only product change is [SchemaRegistry.createField](../src/lib/server/database/registry.ts): required new string/text columns receive `NOT NULL DEFAULT <explicit default or ''>`; optional new columns receive no SQL DEFAULT even when explicit default metadata exists; `unique` is stored as metadata without creating a field-specific SQL index. There is no retrofit, migration, content-validation change, shared-bug fix, deployment or release.

This verified inherited bug is deferred in this repository's [issue #20](https://github.com/sveltery/cms/issues/20). Per-locale content slug uniqueness and system/metadata constraints remain independent. Optional SQL NULL stays SQL NULL rather than taking metadata default values.

Existing tables remain divergent pending a separately reviewed upgrade. In particular, old optional SQL defaults, old unique field indexes, and old required columns lacking SQL defaults retain their physical behavior after reopen. The repair changes the creation of future columns only, including additions to existing collections; it does not recalculate old fields from metadata or remove their indexes. The legacy disposable fixtures prove old NULL/stored values, default definitions and index enforcement survive reopen unchanged. This is not an EmDash database import or schema-wide parity claim.
