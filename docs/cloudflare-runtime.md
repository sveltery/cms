# Native Cloudflare D1 runtime

The [revision hosting slice](revision-hosting.md) adds a revision-only scheduled handler beside the unchanged official adapter fetch entry. Operators own trigger configuration; full system cleanup and deployed scheduling remain unfinished.

This feature adds an official adapter-cloudflare build and local workerd/D1 execution in [PR #47](https://github.com/sveltery/cms/pull/47). It extends the configured Node/raw-D1 runtime without provisioning external resources. Final-head CI, independent review and project-manager approval remain pending.

Pinned EmDash 1.1.0 `913cb1bb9b7f08c3ff0d258b4420e53835b6a58e` supplies the D1 request bookmark, session guard, coalescing and missing-binding assertions. [The source ledger](cloudflare-runtime-ports.json) records exact blobs and truthful test-first evidence. The first actual baseline runs fourteen complete declarations: three pass and eleven fail at assertions. Nine guard declarations are copied before implementation but receive no baseline red credit because that API is absent.

D1 REST migration CLI, the complete upstream migration-lock universe and other hosting adapters remain future scope. Canonical local migrations continue through the existing reviewed provider; this feature does not rename upstream migration assertions to claim coverage. Local Worker execution is separate from deployed Cloudflare evidence.

The native hook resolves the stored session on the raw binding before selecting a request-scoped D1 session. Writes use `first-primary`; authenticated reads can resume a valid opaque bookmark. The source hang guard and coalescing driver retain their pinned algorithms. Anonymous requests omit bookmark cookies; a request that issues the ordinary session cookie can persist its bookmark.

SvelteKit forbids `cookies.set` after `resolve` has generated a response. The built-Worker test exposed an actual HTTP 500 at bookmark commit before the repair. On a returned response, the native boundary uses Kit's cookie serializer and appends the serialized bookmark to that response, retaining the source path, HttpOnly, SameSite and protocol-dependent Secure options and commit timing. If `resolve` throws, the hook commits through the original Kit cookie-jar setter captured before rendering, so Kit's outer error response can include the completed bookmark. A commit failure remains defended and cannot replace the original render error. The success path never calls a post-response cookie setter. This is the RT2-03 framework substitution, with no changed source expectations. A prior unconfigured-fixture expectation of 503 was incorrect: the existing remote boundary returns 401/UNAUTHENTICATED. That fixture correction earns no red credit. Earlier Miniflare import/setup failures likewise earn none.

Recovery verification passed all 23 complete source declarations and six supplemental tests, including the actual bundled Worker HTTP boundary, concurrent canonical startup, persisted D1 reopen, current-role changes, disabled/revoked sessions, authentication before request scoping, write/bookmark constraints, waitUntil forwarding and the outgoing bookmark. These checks use an ordinary persisted opaque session fixture; they do not establish passkey provisioning or deployed availability. The supplemental scope fixture initially used a noncanonical token and failed during setup; correcting it to an encoded 32-byte token earned no product red credit.

Use Node 24 and pnpm 12.6.0. `pnpm build:cloudflare` builds through official adapter-cloudflare 7.2.9 and bundles a dry-run Worker with Wrangler 4.99.0. Kit 2 remains pinned; adapter 8 requires Kit 3. `pnpm test:cloudflare` runs the unchanged source assertions and the built Worker tests. The normal bootstrap now includes both commands after its existing default/Node checks. Local/dry-run Wrangler configuration and logs stay in ignored `.wrangler/config` and `.wrangler/logs`.

For local use, build first, then run `pnpm start:cloudflare`. The committed `wrangler.jsonc` declares `CMS_DB`, local public origin `http://127.0.0.1:8787`, automatic sessions and query coalescing. Its database ID is a placeholder for local execution. For operator-managed deployment, supply the real database ID and exact public origin using the ordinary Wrangler configuration workflow; this change performs no deployment. `SVELTERY_D1_BINDING` selects another trusted binding name, `SVELTERY_D1_SESSION` accepts `disabled`, `auto` or `primary-first`, and `SVELTERY_D1_BOOKMARK_COOKIE` selects a bookmark cookie name. Missing explicitly named bindings fail with `BINDING_NOT_FOUND`; an unconfigured application retains the existing fail-closed behavior.

The Worker build substitutes an explicit D1-only loader for Node SQLite. Tests verify that the actual bundle contains no `node:sqlite` import or test-session fixture. Default and Node builds retain their existing adapter selection. Remote REST migrations, source migration locks, Durable Objects, Hyperdrive and external provisioning remain unimplemented scope, as recorded in RT2-02; the passing bounded source ports confer no credit for those omissions.

Independent PR review found that the native `CmsDatabase.atomicBatch` facade could bypass the coalescing driver's physical-operation chain. Six supplemental regression cases were committed before repair (`f7601f6`): three plain-session cases passed and three coalescing cases failed at `maxInFlight === 1`, observing two simultaneous operations. The native adapter now shares one connection with its driver, drains previously queued reads into that connection's chain, then enqueues the atomic write. Exact order, completed bookmark, rejected-write propagation and later-read recovery pass in all six cases. The existing source `executeQuery`, enqueue and flush algorithms and all 23 whole source declarations remain unchanged. These regressions earn no source parity credit.

The pinned upstream helper also bypasses the chain; this is verified against eight complete, unedited source modules and tracked in [issue #51](https://github.com/sveltery/cms/issues/51). Its helper overlaps physical operations in both plain and coalescing modes. The native facade already serialized plain-session batches; this explicit RT2-04 native extension adds the same stronger queue/order guarantee to coalescing. It is an intentional native behavior difference, not a claim that the pinned helper has been faithfully repaired. Specific acceptance is unrecorded and PR approval remains pending. The [source proof](cloudflare-atomic-source-proof.json) and [reproducer](../scripts/probe-cloudflare-atomic-source.mjs) retain source blobs and host-only import substitutions.

To repeat that source-only probe, install `kysely@0.29.2` and `kysely-d1@0.4.0` into a separate tools directory, then run `node scripts/probe-cloudflare-atomic-source.mjs /path/to/pinned-emdash /path/to/tools`. It verifies the eight recorded Git blobs/SHA256 values, copies their complete bytes to a temporary directory, uses Node's TypeScript transform and host import aliases, and asserts the observed two-operation source limit. It runs no CMS product tests and changes no source assertions.

Final review also exposed a throwing-boundary bookmark loss: successful serialization buffered the cookie, then a propagating error discarded that private buffer. Test-first `19f32e5` reproduced two genuine assertion failures after completed real D1 writes, using Kit 2.70.3's actual cookie jar and its outer header propagation. Repair `0baa1fe` passes both, preserves the original exception, persisted row, unrelated cookie, error body/header/status and bookmark flags, including Kit's public-setter replacement. These are bounded native throwing-seam checks, not whole-Worker error claims: ordinary Kit route failures often return a Response. The actual built Worker additionally checks a missing-content error envelope and its read bookmark through the success response handoff. Final-head CI and independent/configured closure remain required.
