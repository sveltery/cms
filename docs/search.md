# Full search

This feature targets pinned EmDash 1.1.0 `913cb1bb9b7f08c3ff0d258b4420e53835b6a58e`: ordinary full-text queries, suggestions, ranking, opaque offset pagination, locale/title filtering, index administration and product integration. The existing content-picker `FTSManager` remains the single FTS producer. Source copyright is 2026 Cloudflare Inc., MIT; [the notice](../notices/emdash-MIT.txt) applies to all copied code/tests.

The first checkpoint adds 14 whole core families, the remaining nine whole integration/UI/MCP/browser families as inventory, and nine supplemental Native real-SQL query cases. Every upstream callback, assertion expression, dataset and deadline is preserved byte for byte. [The source ledger](search-source.json) and `scripts/check-search-source.mjs` protect that provenance. No product tests have run at this proposal checkpoint, no runtime search implementation has been applied, and no Source causal assertion credit or completed search acceptance is claimed.

The executable transport uses canonical Node SQLite, real Native schema/content repositories and the existing FTS producer. The Source registry constructor and `updateCollection` CAS are adapted at the fixture import boundary. Three whole families still reference real Source `_emdash_fts_*` objects or a `_emdash_collections` builder: the Native producer's `_cms_fts_*` namespace cannot satisfy those original raw-name observations. The transport leaves the raw SQL, catalogue, literal and result bytes unchanged. A separate exact proposal must bind the same producer and query algorithms to real Source-name fixture tables, using only builder-level metadata aliases. Production default-name counterparts remain independently necessary.

Actual schema-to-FTS lifecycle hooks are also missing in the Native registry. Test setup does not create synthetic schema hooks to hide that gap. The new query engine and schemas are absent at the public baseline; missing product imports or pre-expect/fixture stops receive zero Source behavioral red credit. The eight Native query requirements assert module readiness before their later real query values; the ninth case verifies existing real FTS and content storage.

The pinned routes make search and suggestions public and force published status unless current trusted locals permit `content:read_drafts`. Index stats/enable/rebuild require `search:manage`. The persisted principal bridge needs a finite reviewed additive mapping because its current service permission allowlist omits that already-defined administrative permission. No new identity subsystem or credential/session/signature/race/protected HTTP probes are introduced by this test checkpoint.
