# Inventory identity, assertions, and scope

The catalog lets a port reviewer find the exact upstream case and check that its expected behavior survived framework adaptation. It inventories selected tests; it does not claim to cover every relevant upstream test. Add cases discovered while implementing a feature before claiming that feature's port is complete.

## Stable source identity

Each declaration has a `sourceId` of `commit:path:declaration-line`, its exact `title`, ordered ancestor `suites`, original `registration`, source URL, and SHA-256 of the registration source. Each file records its Git blob ID and SHA-256 of the entire file. Every extracted assertion preserves its exact expression, source line, and pinned source URL, including `.not`, `.resolves`, `.rejects`, and `await` where present. Asymmetric matcher constructors such as `expect.objectContaining` are retained inside the enclosing assertion, not counted as independent assertions.

Keep the source ID beside the ported test or in a checked-in mapping. Local test titles can add the source ID and runtime suffix; never replace the original identity with a new paraphrase. Preserve the fixture inputs, expected values, negative checks, row counts, side effects, ordering, error codes, and no-mutation checks. The source link is authoritative for hooks, imported helpers, and fixture context; an isolated assertion expression is insufficient to reconstruct a test.

`sharedAssertions` records assertions in setup and shared functions outside individual test callbacks. Associate relevant helper assertions with each ported caller after tracing the source. They are not independent test cases. One selected declaration (`packages/core/tests/database/repositories/content.test.ts:597`, “accepts locale as an order field”) has no direct matcher; it requires successful completion and must not be credited with an invented upstream assertion.

## Expand declarations into executable cases

The catalog counts registrations, not execution. The `expansion` array retains `.each` registration text and enclosing parameterized suites. `loopContexts` retains source references for loop-generated registrations. `runtimeGates` retains explicit skip/runIf/fixme calls at file and test level, including in-body Playwright skips; read their condition and hooks at the linked source. Fixtures and datasets referenced by identifier must be read at the pinned source; the extractor does not evaluate them.

When porting:

1. Expand `.each` inputs, describe parameters, loop values, feature flags, permissions, locales, and fixtures into named concrete cases. Give each case a local suffix containing the dataset value/index and runtime. Keep the common source ID.
2. Upstream `describeEachDialect` expands to SQLite, plus PostgreSQL only when `EMDASH_TEST_PG` is set (`packages/core/tests/utils/test-db.ts:574`). A SQLite pass does not imply PostgreSQL or D1. Record skipped upstream dialect cases separately. D1 requires a corresponding workerd test or explicitly added adaptation case.
3. Keep `.skip`, `.skipIf`, `.only`, `.fixme`, conditional registrations, and runtime gates visible. The catalog stores their registration/context; the port reviewer must read the file's hooks and runtime conditions. Do not count a registered, filtered, skipped, or unrun case as passed.
4. Separate expected platform adaptation from upstream assertions. A different local API name/import/selector can map the same behavior; a changed error, default, ownership rule, transaction outcome, timestamp, or lifecycle requires a ledger entry.
5. Test the actual product service/repository with real persistence for storage behavior, and the SvelteKit HTTP/browser boundary for transport behavior. An in-memory fake may prove denial avoids calls; a copied algorithm or test-only CMS implementation cannot establish product behavior.

## Evidence states and expansion policy

Maintain a separate per-case port mapping when executable tests are added. Use `inventory-only`, `ported-red`, `ported-green`, `blocked`, or `documented-deviation`, with local test path/title, source ID, expanded dataset, target runtime, implementation commit, and actual run evidence. A blocked case names its dependency/owner. A documented deviation links its ledger rationale and regression tests; it is not an upstream pass.

Before each new feature slice, search the pinned upstream for its handlers, repositories, admin behavior, e2e cases, and adapter regressions. Extend `selection.json`, regenerate, and review newly discovered assertions. Track exclusions by source ID where known and by named family otherwise. Deferred families include media/assets, rich editor rendering, plugins/sandbox, taxonomies/bylines, locale/translation, public loaders/cache/redirects, scheduling, import/export, and additional database adapters. Some dependent cases are already visible in selected whole files; keep them blocked/deferred until the associated feature is implemented. Self-hosted CMS scope excludes EmDash hosted registry/release/aggregator services; it does not justify losing Node hosting or database-defined schemas.
