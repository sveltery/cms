# Bounded ports and worker contracts

Port the selected test assertions first, demonstrate their failures against CMS product code, then fix the implementation. Keep a failing case visible until its feature is implemented or its platform difference is documented. An import/registration failure is a harness blocker; obtain an assertion-level red run before crediting the test-first behavior change. Preserve all assertions of each selected case, including fixture/helper checks and negative side effects.

The exact declaration IDs and titles for the initial candidates are in [first-slices.json](first-slices.json); [inventory.json](inventory.json) contains their original assertions and surrounding suite identity. The numbers below are source declarations before parameter/runtime expansion. These slices are proposals for the parent to reconcile with the implementation workers' current branches.

S1 and S2 can proceed in the existing workers, coordinated through the parent. S3 consumes their agreed contracts. S4 and S5 must pass before published editing or concurrent publishing is advertised. S3's recoverable delete requires trash tests from the start; the order does not authorize an interim physical delete. S5 covers publication CAS candidates, but ordinary update CAS and edit-lock expiry/session/takeover cases also gate multi-editor use. Include schema validation errors and unsupported stored-type regressions as soon as their storage paths exist.

Keep exact fixture types when porting. The registry field-list case at line 634 creates a `portableText` field and stays in inventory until that metadata/storage support exists; add an explicitly local scalar-list check for S1 instead of rewriting its fixture and calling it an exact upstream port. S3 repository fixtures also define `portableText`, and selected cases use complex `data`; those ports need the matching field metadata and JSON storage support even while rich editor rendering remains deferred.

Every persistence slice needs a Node SQLite run and an equivalent local Cloudflare workerd/D1 run with the same behavioral expectations. D1 is not another expansion of upstream `describeEachDialect`; register explicit runtime cases. Cloudflare missing-bindings, request/session scoping, DDL recreation, migration locking/idempotence, and batch/affected-row tests enter alongside the relevant adapter code. A platform failure is a blocked slice or ledger proposal, not a waived check. No cloud resource creation or deployment is needed for local adapter evidence.

## Contracts to reconcile through the parent

The parent owns decisions affecting shared services/routes/CI. This worker owns inventory, parity documentation and notices only. It does not duplicate either implementation worker.

| Owner | Inputs and proposed product contract | Required handoff evidence |
| --- | --- | --- |
| Schema/persistence worker `01a0f87a-3fc9-77a0-aafc-671363ae500f` | S1 and S3 source IDs; database-defined collection/field records and generated validation; collection-qualified content identity; arbitrary `data`; explicit supported features; owner/status/locale/timestamps; revision token and draft/live pointers when those features enter | Exact exported product interfaces and error types, migration/storage guarantees, source-ID test mapping, assertion-level red/green runs, restart persistence, Node/D1 status and blocked cases. Never hide a final implementation in a test helper. |
| Remote/denial/browser worker `01a0f879-66c7-71ff-8ee2-f9941edd9003` | S2 IDs and browser inventory; native registered remote `query`/mutation exports; server-resolved identity; collection-qualified arguments; reject caller identity/capability injection; schema validation and permission checks before writes | Built endpoint registration, real HTTP/browser evidence, anonymous/insufficient/own/any/null-owner cases, validation/no-write checks, native error mapping, query refresh and revision-token propagation. Test actual remote protocol rather than calling only a service mock. |
| Parent | Reconcile these contracts before landing incompatible worker slices | Decide module/export ownership, collection/data input shape, role/ownership contract, `_rev` transport, domain-to-native error mapping, Node/Cloudflare adapter boundary, and documentation reconciliation. Route corrections A-01 through A-08 in the ledger to the relevant owner. |

The proposed shape is semantic, not a fixed TypeScript interface: collection slug plus item ID/slug and locale for lookup; schema-defined `data` for content; trusted server actor for ownership; distinct trash/restore/permanent-delete; `_rev` for conditional mutations; explicit draft/live state. Exact names and wire envelopes require a parent decision. Keep existing scaffold export names only if they can express those semantics without weakening source assertions.

For S1 browser acceptance, create a collection and field through the dashboard, reload/new request, and create/read content whose shape comes from that stored definition. For S3, use the same exported forms/queries as the UI, reload after writes, and check list/detail refresh and not-found after trash. Upstream browser helpers such as `devBypassAuth` are harness context; create trusted test sessions through the native test setup without adding a product authorization bypass. Browser/registration/reopen tests added for the native port are **supplemental local requirements**, not copied EmDash cases unless an exact source ID is mapped.

## Record executable evidence

Each implementation PR includes a per-expanded-case mapping with upstream ID/title/assertions, local file/title, fixture/dataset, Node or workerd target, red commit/result, fix commit/result, skips/blockers, and linked deviations. Report upstream-derived tests separately from original local requirements and harness checks. Preserve notices in copied files and distributed artifacts.

Before claiming a family complete, inspect the neighboring source cases and extend the catalog for omitted edge cases. A narrow first slice can pass without completing its family. Never report an unsupported parity percentage, aggregate green inventory entries, or product correctness from fixture-only tests.
